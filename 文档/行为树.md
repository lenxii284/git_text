```python
#创建定时器
timer_ = this->create_wall_timer(500ms, std::bind(&MinimalPublisher::timer_callback,
this)
#std::bind(&MinimalPublisher::timer_callback, this)：
这是将成员函数绑定为定时器的回调函数，其作用相当于“告诉定时器：每次触发时，请调用当前对象的 timer_callback 方法”。

&MinimalPublisher::timer_callback：取类 MinimalPublisher 的成员函数 timer_callback 的地址（注意是函数指针，不是调用它）。

this：将当前对象的指针作为第一个参数传入，确保回调在正确的对象实例上执行（因为成员函数需要 this 指针）。

本质上：std::bind 将成员函数和对象绑定在一起，生成一个可调用对象（仿函数），供定时器在触发时调用。(bind可以翻译为绑，约束)
```

```python
#订约方实现
subscription_ = this->create_subscription<std_msgs::msg::String>("topic", 10,
std::bind(&MinimalSubscriber::topic_callback, this, _1));
#&MinimalSubscriber::topic_callback：取类 MinimalSubscriber 的成员函数 topic_callback 的地址（函数指针）。
#this：传入当前对象的指针，确保回调在正确的对象实例上执行（因为成员函数需要 this）。
#_1：占位符（placeholder），表示"回调函数的第1个参数由订阅者系统在运行时传入"。

_1的写法可以使用Lambda替换
示例
// 使用 Lambda（不需要 _1）
subscription_ = this->create_subscription<std_msgs::msg::String>(
    "topic", 10,
    [this](const std_msgs::msg::String::SharedPtr msg) {  // msg 直接是参数名，不是占位符
        topic_callback(msg);  // 或者直接处理
    }
);

```

回调函数后面跟一个const可以避免修改成员变量
```
void topic_callback(const std_msgs::msg::String & msg) const
//                                                   ↑
//                                         这个const修饰的是成员函数本身
第1个 const（参数前）：表示 msg 是常量引用，函数内不能修改消息内容。

第2个 const（函数末尾）：表示这个成员函数是常量的，函数体内不能修改类的任何成员变量（除非成员变量声明为 mutable）。

void callback() const	 不能修改成员变量	             不能调用非const成员函数	      纯读取逻辑，如日志打印、统计查询
void callback()	       能修改成员变量	               能调用非const成员函数	      需要更新状态，如计数器++、缓存更新

```
## 自定义消息内容后如何使用

在使用自定义消息内容的节点中可以添加上
```python
using base_interfaces_demo::msg::Student;
base_interfaces_demo：这是你自定义的消息包名（功能包名称），通常是你自己创建的ROS2接口包。

msg：固定命名空间，表示消息定义（对应 .msg 文件）。

Student：你自定义的消息类型名称，对应 Student.msg 文件。
```

添加上这句话了后在后续的调用中就可以直接调用Student，而不需要写完整的消息内容
```python
// 先声明 using
using base_interfaces_demo::msg::Student;

// 之后可以直接用 Student
Student student_msg;  // 简洁！
student_msg.name = "张三";
student_msg.age = 18;
```

## 服务通信
服务通信中在代码开头会引入
```python
using std::placeholders::_1;
using std::placeholders::_2;
std::placeholders：C++标准库中定义的占位符命名空间。

_1：表示"回调函数的第1个参数"。

_2：表示"回调函数的第2个参数"。

作用：告诉 std::bind，"这些参数位置将在函数被调用时由ROS2系统传入，而不是现在绑定固定值"。

示例：
server_ = this->create_service<ServiceType>(
    "service_name",
    std::bind(&Class::handle_service, this, _1, _2)
    //                                    ↑    ↑
    //                                   请求  响应
);

_1 对应回调函数的第1个参数（请求）

_2 对应回调函数的第2个参数（响应）

这两个参数在服务被调用时由ROS2自动传入
```
客户端中的一些内容
```python
auto response = client->send_request(atoi(argv[1]), atoi(argv[2]));
//                                   ↑              ↑
//                              第1个整数参数    第2个整数参数
client->send_request(...)：调用服务客户端的 send_request 方法，发送服务请求。

argv[1] 和 argv[2]：从命令行接收的两个参数（字符串形式）。

atoi()：将字符串转换为整数（a = ASCII, to = to, i = integer）。
```

#  `Lambda`

使用`Lambda`表达式可以直接把回调函数写入`Public`的定义对象中例如
```python
// 订阅话题，使用Lambda表达式作为回调
subscription_ = this->create_subscription<std_msgs::msg::String>(
    "topic", 10,
    [this](const std_msgs::msg::String::SharedPtr msg) {
        RCLCPP_INFO(this->get_logger(), "I heard: '%s'", msg->data.c_str());
        // 在这里处理接收到的消息
    });

    原始写法：

// 需要先在类中声明一个成员函数
void topic_callback(const std_msgs::msg::String::SharedPtr msg) {
    RCLCPP_INFO(this->get_logger(), "I heard: '%s'", msg->data.c_str());
}

// 在构造函数中，使用std::bind绑定
subscription_ = this->create_subscription<std_msgs::msg::String>(
    "topic", 10, std::bind(&MinimalSubscriber::topic_callback, this, _1));
```

# 基本骨架

```python
<root main_tree_to_execute="MainTree">
  <BehaviorTree ID="MainTree">
    <!-- 在这里构建你的节点树 -->
    <Sequence name="root">
      <ComputePathToPose goal="{goal}" path="{path}" />
      <FollowPath path="{path}" />
    </Sequence>
  </BehaviorTree>
</root>

# <root>:XML 文件的根节点，必须包含 main_tree_to_execute 属性，指定要执行的主树 ID。
# <BehaviorTree>: 定义一棵具体的行为树，其 ID 属性被 main_tree_to_execute 引用。
# <Sequence>、<Fallback>: 控制节点，用于组织子节点的执行逻辑，如顺序执行、备选执行等
# <RateController>: 装饰器节点，用于控制其子节点的执行频率，例如 1 Hz
# <ComputePathToPose>、<FollowPath>: 动作节点，执行具体的导航任务，如规划路径、控制机器人跟随路径
# <GoalReached>、<IsStuck>: 条件节点，用于检查系统状态，如是否到达目标、是否卡住
#goal="{goal}": 端口（Port），用于在节点间传递数据，语法为 "{变量名}"，数据通常存储在黑板（Blackboard）上
```
## 参数示例：

`<ComputePathToPose>: 调用规划器计算路径。` 

```python
<ComputePathToPose goal="{goal}" path="{path}" planner_id="GridBased" />
```

`<FollowPath>: 调用控制器跟踪路径。`
```python
<FollowPath path="{path}" controller_id="FollowPath" />
```

`<RateController>: 以指定频率（Hz）执行子节点，常用于路径重规划。`
```python
<RateController hz="1.0">
  <ComputePathToPose goal="{goal}" path="{path}" />
</RateController>
```

`<ClearEntireCostmap>: 服务节点，用于清除代价地图。`
```python
<ClearEntireCostmap name="ClearGlobalCostmap" service_name="global_costmap/clear_entirely_global_costmap" />
```

`<Spin> / <BackUp>: 旋转和后退动作，通常作为恢复行为（Recovery Behavior）`
```python
<Spin spin_dist="1.57" />
<BackUp backup_dist="0.15" backup_speed="0.025" />

```
## 示例

```python
<root main_tree_to_execute="MainTree">
  <BehaviorTree ID="MainTree">
    <PipelineSequence name="NavigateWithReplanning">
      <RateController hz="1.0">
        <ComputePathToPose goal="{goal}" path="{path}" planner_id="GridBased"/>
      </RateController>
      <FollowPath path="{path}" controller_id="FollowPath"/>
    </PipelineSequence>
  </BehaviorTree>
</root>给我解释这个行为树
```
### 1.整体结构

```python
<PipelineSequence name="NavigateWithReplanning">
  <!-- 子节点1 -->
  <!-- 子节点2 -->
</PipelineSequence>

作用：PipelineSequence 是 Nav2 特有的一个控制节点，它允许其所有子节点同时运行（并行），但要求它们必须按顺序初始化和按顺序完成。
在这个树里的体现：ComputePathToPose（规划）和 FollowPath（控制）会同时处于活动状态。这意味着机器人在移动（执行 FollowPath）的同时，后台也在不断地计算新路径（执行 ComputePathToPose）。
```

### 2.重规划部分：<RateController> + <ComputePathToPose>

```python
<RateController hz="1.0">
  <ComputePathToPose goal="{goal}" path="{path}" planner_id="GridBased"/>
</RateController>

<RateController hz="1.0">：这是一个装饰器节点，它会以 1 Hz（每秒 1 次）的频率“滴答”（tick）其唯一的子节点。

<ComputePathToPose>：这是动作节点，负责调用规划器（planner）计算从当前机器人位置到 {goal} 的路径，并将结果存入 {path} 变量。

组合效果：这个组合块每秒钟都会重新计算一次全局路径。它会持续更新 {path} 这个黑板变量。
```

### 3. 路径跟踪部分：<FollowPath>

```python
<FollowPath path="{path}" controller_id="FollowPath"/>

作用：这是动作节点，负责调用控制器（controller）来驱动机器人，使其沿着黑板上的 {path} 变量所指向的路径移动。

关键点：因为它与规划块并行运行，所以 FollowPath 会实时读取被 RateController 不断更新的 {path} 变量。
```

### 4. 整体运行流程（时间线）

```python
初始化：PipelineSequence 启动，先执行第一个子节点（规划块），获得一条初始路径。

并行执行：一旦初始路径就绪，PipelineSequence 会立即启动第二个子节点（跟踪块），机器人开始移动。同时，规划块依然以 1 Hz 的频率在后台运行。

持续更新：每隔 1 秒，RateController 触发一次 ComputePathToPose，它会基于机器人当前的最新位置重新计算一条到目标的路径，并更新黑板上的 {path}。

动态响应：FollowPath 节点会持续监控 {path} 的变化。一旦发现路径被更新，它会平滑地切换到新的路径上，从而实现对动态环境（如突然出现的障碍物）的快速响应。

```

```python
一.在launch启动文件中传递新行为树的路径
ros2 launch nav2_bringup bringup_launch.py \
  use_sim_time:=True \
  map:=/path/to/your/map.yaml \
  params_file:=/path/to/your/nav2_params.yaml \
  bt_xml_file:=/path/to/your/workspace/src/my_robot_nav2/behavior_trees/follow_point.xml

    bt_xml_file: "/path/to/your/workspace/src/my_robot_nav2/behavior_trees/follow_point.xml"

```

示例：
```python
class MyNode : public rclcpp::Node

    }

    }
```

## [launch启动文件解读](https://github.com/ros-navigation/navigation2/blob/main/nav2_map_server/launch/vector_object_server.launch.py)

### 第一部分

声明功能包，使用`get_package_share_directory`声明
使用`lifecycle_nodes`管理需要受到生命周期管理的节点 格式为lifecycle_nodes = ['','']
使用`remappings`把话题重映射为相对名称

### 第二部分

引用声明需要使用的变量名称 使用`LaunchConfiguration`声明 格式为`xx = LaunchConfiguration('xx')`

### 第三部分

使用`DeclareLaunchArgument`声明参数 格式为声明参数名称 = `DeclareLaunchArgument`(
    '引用参数名称', `default_value`='', `description`='')
  
### 第四部分

`RewrittenYaml`：读取 `params_file`，把 `YAML` 顶层根键替换为 `namespace，convert_types=True` 自动把字符串转成 `bool/int/float`。

P`arameterFile`：包装成延迟加载的参数描述，`allow_substs=True` 允许参数值里用 `$(var ...) `等 l`aunch` 替换。

为什么这么写？ 让同一份 `YAML` 能被不同命名空间复用。例如 `namespace=robot1` 时，`YAML` 里 `robot1:` 下的参数就会被提取出来。

### 第五部分(独立进程模式)

`GroupAction：`把一组动作打包，方便统一加条件。

`condition=IfCondition(PythonExpression(['not ', use_composition]))：`只有 `use_composition` 为假时才执行这组动作。`PythonExpression` 会拼接成 `not <use_composition的值>`。
`PythonExpression` 可以“提取”这些变量的值，代入表达式进行计算，并返回结果类似于 `if` `a` == `b`的形式

`SetParameter('use_sim_time', use_sim_time)：`在 `launch `全局作用域设置 `use_sim_time `参数，后续节点会继承。

`PushROSNamespace：`如果 `namespace` 非空，就把命名空间压入作用域栈。这是个作用域动作，其后的节点都会自动套上该命名空间。条件用`NotEqualsSubstitution` 判断命名空间不等于空字符串。
`NotEqualsSubstitution` 是 `ROS 2 `启动系统中的一个替换（`Substitution`）类，用于在启动文件运行时判断两个输入是否不相等，并返回字符串 `'true'` 或 `'false'`

启动节点中`output='screen'：`日志输出到终端。

`emulate_tty=True：`模拟 `TTY`，让彩色日志正常显示（这是为了绕过 `ros2/launch#188` 的问题）。

`parameters=[configured_params]`：加载前面构造的参数。

`remappings=remappings：`应用 `TF` 重映射。
其中生命周期节点的参数内容为`parameters=[{'autostart': autostart},`
            `{'node_names': lifecycle_nodes}]`

### 第六部分(组合节点模式) 仅仅支持c++暂时不支持python
这部分与节点模式逻辑镜像，区别在于：

条件相反：`IfCondition(use_composition)`，只有为真时执行。

用 `LoadComposableNodes：`把节点作为 `ComposableNode` 加载到 `target_container=container_name `指定的容器中。

用 `ComposableNode `而非 Node：注意它用的是 `plugin= `而不是 `executable=`，因为组合节点是通过插件类名加载的：

`plugin='nav2_map_server::VectorObjectServer'`

`plugin='nav2_map_server::CostmapFilterInfoServer'`

`plugin='nav2_lifecycle_manager::LifecycleManager'`

使用组合节点，多个节点共享同一进程，进程内通信可以零拷贝，降低延迟和` CPU `占用，是 `Nav2 `的推荐部署方式。
